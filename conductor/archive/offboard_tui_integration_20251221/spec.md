# Track Specification: Stabilize IAM Offboarding & Integrate with TUI\n\n## Context\nThe `iam:offboard` module is currently in progress. The logic for user blocking, session revocation, and basic license removal is partially implemented in `core/src/commands/iam/offboard.ts`. The Rust CLI has a basic structure but needs to fully expose this command in the TUI (Terminal User Interface).\n\n## Goals\n1.  **Refine Core Logic:** Ensure the `offboardUser` function in TypeScript handles all edge cases (e.g., users without managers, group-based license inheritance) robustly and reports status via IPC.\n2.  **TUI Integration:** Implement the UI flow in the Rust application to trigger the `iam:offboard` command. This includes:\n    -   An input form to select the user (via email or search).\n    -   Optional manager selection.\n    -   A "Dry Run" toggle.\n    -   Real-time progress streaming from the backend.\n3.  **Validation:** Verify end-to-end execution from TUI -> Rust process -> Bun worker -> Graph API.\n\n## Requirements\n-   **TypeScript Backend:**\n    -   Validate license removal logic (Group vs Direct).\n    -   Ensure consistent JSON IPC output for "Success", "Error", and "Progress" states.\n    -   Implement "Shared Mailbox conversion" notice (or automation if API permits).\n-   **Rust Frontend:**\n    -   Update `cli/src/ui.rs` or `cli/src/tui.rs` to add the "Offboard User" form under the IAM tab.\n    -   Use `inquire` or `ratatui` widgets for user input.\n    -   Parse the IPC JSON stream and render it to the real-time logs panel.\n\n## Out of Scope\n-   Automated PowerShell execution for Exchange-specific tasks (this remains a manual step or legacy script wrapper for now).
